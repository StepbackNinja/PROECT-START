# START — передача проекта в новый чат

## Что это

START — русскоязычное mobile-first PWA для iPhone: помогает начать дело с одной пятиминутной миссии. Основной проект — React 19, TypeScript, Vite, PWA; серверные напоминания работают через Supabase Edge Function и Postgres. Аккаунтов нет. Локальный прогресс привязан к домену и браузеру устройства.

## Текущее состояние

- Космический редизайн работает по адресу с `?design=cosmos`, исходная версия остаётся на основном адресе.
- Космический фон качественно повышен ранее; пользователь заметил потерю качества при последующих изменениях. После сравнения восстановлен первоначальный фон, а тату добавлено отдельной композицией. В последнем изменении фон и персонаж объединены послойно, без повторной генерации всей сцены.
- Для портретной композиции создана пара образов: с открытой спиной и в светлом костюме цвета слоновой кости. Короткие светлые волосы, посадка, дым и сигарета взяты по референсам пользователя. Тату приблизительно перенесено на поднятую левую руку/плечо. Пользователь утвердил образ и просил больше не переделывать кисть. Не генерировать персонажа/кисть заново без прямой просьбы.
- Оба изображения 1764×1764, WebP примерно 0,8 МБ. Картинки статичны; отдельные неброские слои света и точек мерцают только над небом. В CSS отключён zoom/drift портрета, чтобы не смягчать детали. Визуально проверено в Chrome при 390×844.
- Портреты чередуются при новой загрузке. Если миссия активна, выбранный образ сохраняется при перезагрузке. Состояние миссии, серия и XP не меняются этой логикой.
- Композиция космической версии удлинена: портрет сверху, таймер под ним. Вся страница прокручивается; на тестовом размере персонаж виден полностью, блоки серии/напоминаний остаются ниже.
- Таймер, XP, серия, календарь, недельная заморозка и push логика используют прежний `App.tsx` и `storage.ts`.
- Последняя проверка: `npm run build` прошёл. Проверка `work/verify-portrait.mjs` подтвердила чередование, стабильность образа в миссии и сохранение прогресса. `work/verify-mission-control.mjs` подтвердил состояние и действие таймера. Ручная проверка на настоящем iPhone ещё нужна.
- Изменения закоммичены и отправлены в `main`; на момент передачи рабочее дерево было чистым.

## Запуск и проверка

В терминале из корня проекта:

```sh
npm install
npm run dev
```

Сборка: `npm run build`. Для iPhone нужен production HTTPS URL; открыть в Safari и выбрать «Поделиться» → «На экран Домой». Чтобы увидеть новый PWA-кеш, открыть приложение с интернетом и перезапустить его. Не очищать данные сайта: там хранится личный прогресс.

## Архитектура важных частей

- `src/App.tsx` — миссия, прогресс, серия, напоминания и календарь.
- `src/CosmicPortrait.tsx` — выбор и закрепление образа при активной миссии.
- `src/CosmosScene.tsx`, `src/cosmos.css` — фон, декоративный свет, стили и анимации космического режима.
- `src/storage.ts` — локальные XP, серия, заморозка, дедлайн таймера.
- `src/reminders.ts`, `public/push-worker.js` — клиентские push-напоминания.
- `supabase/functions/start-push/index.ts`, `supabase/schema.sql`, `supabase/scheduler.sql` — серверные напоминания и расписание.
- `public/assets/portrait-bare-v1.webp`, `public/assets/portrait-suit-v1.webp` — пара образов.
- `outputs/start-living-cosmos-iphone.jpg` — скриншот космической страницы при ширине 390 px.

Секреты Supabase/VAPID не добавлять в Git и не выводить в чат. Не менять VAPID ключи: существующие подписки зависят от них.

## Следующие разумные шаги

1. Попросить пользователя открыть космический адрес на iPhone и проверить визуально: резкость, целиком ли виден персонаж, не слишком ли длинная прокрутка, насколько мягко выглядит свет.
2. Уточнить по отзыву только реальные проблемы. При дефекте движения исправлять отдельный CSS слой; исходные изображения не перегенерировать.
3. Перед любым продвижением космического дизайна на основной адрес получить ясное решение пользователя. Пока космос — opt-in через `?design=cosmos`.
4. Не менять таймер/серии/push в ходе визуальной доводки.

Известное продуктовое ограничение: если миссия идёт через полночь и приложение закрыто, существующая логика зачёта дат нуждается в отдельном анализе; эту задачу не смешивали с редизайном.
