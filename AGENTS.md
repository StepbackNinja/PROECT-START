# START — инструкции для AI-агентов

## 1. Перед началом работы

1. Прочитай `PROJECT.md`.
2. Изучи актуальную структуру репозитория.
3. Проверь текущую ветку и `git status`.
4. Определи, какие компоненты затрагивает задача.
5. Кратко объясни пользователю план действий.

Не считай паспорт заменой исходного кода. Если документ и код противоречат друг другу, сообщи об этом.

## 2. Основные правила

- Одна задача за один этап.
- Не добавляй функции, которых пользователь не просил.
- Не переписывай работающие компоненты без необходимости.
- Не меняй дизайн за пределами согласованной задачи.
- Не устанавливай новые зависимости без обоснования.
- Не выполняй масштабный рефакторинг попутно.
- Не усложняй архитектуру ради гипотетического будущего.

## 3. Что необходимо сохранять

- Логику пятиминутной миссии.
- Начисление XP и учёт выполненных дней.
- Серию и недельную заморозку.
- Сохранение прогресса в localStorage.
- Систему серверных напоминаний.
- Работу PWA и Service Worker.

Изменения этих механизмов требуют отдельного согласования.

## 4. Дизайн

- Mobile-first.
- Тёмная тема по умолчанию.
- Минимализм и ясная визуальная иерархия.
- Космос и персонаж должны образовывать цельную сцену.
- Таймер — главный интерактивный элемент.
- Анимации деликатные, плавные и производительные.
- Учитывать `prefers-reduced-motion`.

Нельзя заменять утверждённые изображения или менять художественное направление без разрешения.

## 5. Безопасность

- Не публикуй `.env`, токены, пароли и секреты.
- Не выполняй `force push`.
- Не удаляй пользовательские данные.
- Не изменяй production-конфигурацию без разрешения.
- Не выполняй миграции базы данных без отдельного согласования.

## 6. Проверка изменений

После каждой задачи:

1. Запусти доступные проверки, включая `npm run build`.
2. Проверь затронутую функциональность.
3. Убедись, что существующие механики не сломаны.
4. Сообщи, что изменено и что не удалось проверить.
5. Дождись одобрения пользователя перед следующей задачей.

Не утверждай, что функциональность работает, если проверка не проводилась.

## 7. Git и публикация

Не делай commit, push или production deploy без явного разрешения пользователя.

Перед отправкой проверь изменения и отсутствие секретов.

## 8. Формат общения

Пользователь предпочитает короткие объяснения простым языком.

Не перегружай техническими подробностями. Если нужно решение пользователя, задай один конкретный вопрос.

**Главный принцип: сохраняй работающую систему и меняй только то, что необходимо для текущей задачи.**
